# 本周学习与复现路线

目标是在本周形成可核验的小数据 QueST Jittor 复现，保留与 PyTorch 的对齐证据。当前日期为 2026-10-28，目标完成日暂定 11-01。每个模块学习后做一次实际操作，避免一次引入全部命令。

## 模块 1：把现有数据和两阶段方法对应起来（本地即可）

你需要能说清：episode 是一段完整示范，batch 是一次更新取出的样本，action chunk 是未来 32 步动作，8 个 token 表达该动作块。分词器阶段只看动作；策略阶段看图像、8 维机器人状态和 task ID，并学习预测动作 token。这里的单任务版本没有自然语言。

操作：用 `doctor.py` 检查数据；打开训练曲线；从 `data.py` 到 `tokenizer_torch.py` 再到 `policy_torch.py` 跟一遍形状。交付物是你能亲自解释的一张数据流草图。

## 模块 2：Linux 与服务器恢复（需要你打开自己的实例）

学习 `pwd`、`ls`、`cd`、绝对路径、系统盘/数据盘；理解本地终端和 SSH 终端区别；使用 `tmux`，知道断开连接和关机的区别。确认 Python、Conda 环境路径、GPU 驱动、CUDA toolkit 的区别。

操作：正常开机原实例，按平台当前显示的 SSH 命令连接；不要复用过时的端口或密码。运行 `linux_preflight.py`。如果原 GPU 无空闲，先完成本地模块，不为等待而创建额外实例。

## 模块 3：隔离环境与依赖（Linux）

学习 Conda/venv 为什么能隔离依赖、为什么本地环境不能直接复制成 Linux 环境。先理解脚本，再使用 `bootstrap_linux.sh` 分别建立 Torch 与 Jittor 环境。检查 Python 3.10、现有 g++ 和现有 nvcc；脚本不安装系统驱动。

操作：先跑最小 Jittor tensor 前向/梯度/保存恢复；成功后再运行 tiny 模型。把真实错误及修复记录在实验日志中。

## 模块 4：Hugging Face 的实际用途（本地学习即可，非本任务强依赖）

学习 Hub 上 model、dataset、Spaces、model card、revision 的区别；区分下载权重和训练模型。了解 gated/private 资源才可能需要 token，不能将 token 写进代码或 GitHub。

本次 QueST 只用少量 MetaWorld 自采数据和无预训练的视觉编码器，不需要下载 VLM 或多 GB 模型。可先学公开小文件的固定 revision 下载及缓存位置，把 `HF_HOME` 放在工作目录；不为了练习下载大模型，也不必先注册/付费。

## 模块 5：跨框架数值对齐（优先完成）

学习同 seed 不等于同权重；前向值、离散索引、loss、输入梯度、参数梯度、优化器更新分别说明什么。理解 `eval` 不等于不求导，两个框架的 eval 行为也不同。

操作：依次运行 tiny 分词器、完整分词器、tiny 策略、完整策略的对照。打开比较 JSON，看最大绝对误差和失败字段；不通过时定位首个偏差层，不直接放宽阈值。再做固定输入的多步训练对齐。

## 模块 6：训练与评价（数值对照通过后）

学习 L1、交叉熵、teacher forcing、自回归、验证集选 checkpoint、闭环 rollout、训练时间与推理时间。理解低重建误差不能直接推出高任务成功率。

操作：在同一 Linux 机器、同一数据划分、同一初始化/训练计划下跑 Torch 与 Jittor；记录 loss、动作 MAE、成功率、延迟、显存。调试用开发种子 2000+，最终比较用保留的 1000–1019。资源不够时优先完成同一小数据设置的对齐。

## 模块 7：Git、GitHub 与交付（由你做最后发布）

学习工作区、stage、commit、remote、push，理解公开仓库与本地文件的区别。代码、README、小型结果和许可可以入库；密码、环境、缓存、大权重和原始视频不随意入库。

操作：检查 README 中命令和结果均有来源，自己完成仓库创建和发布，记录可公开访问链接。最终用新环境从 README 走一遍。准备 PPT 和视频时，以实际已经跑通的内容为准。
