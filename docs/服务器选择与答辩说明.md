# 为什么使用服务器

本次使用的是配有 RTX 4090D 的 Linux GPU 服务器。服务器不是 QueST 算法成立或获得正确结果的必要条件；具备兼容环境和足够资源的本地计算机同样可以训练和测试。

选择服务器的主要原因：

1. 已经验证过 Linux、CUDA、PyTorch、Jittor 和 MuJoCo 环境，继续实验可以减少重新配置造成的干扰。
2. 便于长时间持续训练和批量仿真，也能尝试在资源允许时同时推进两项实验。
3. 使用 tmux 保存后台会话，关闭本地 SSH 窗口不会主动终止服务器上的任务；实例关机或故障仍会中断任务。
4. 统一环境，记录软件版本、数据和代码哈希、随机种子、训练日志与评价协议，更方便复查。服务器本身并不自动保证可复现。

本机为 RTX 5060 Laptop（约8GB显存）、i9-14900HX、约32GB内存，硬件有希望承担这次小规模实验。但项目当前本地环境是 PyTorch CPU 版，GPU训练和Jittor、仿真兼容性需要重新配置并验证。本轮使用服务器是交付时间和环境成熟度的选择，不代表本机显卡无法训练，也不代表模型必须使用24GB显存。

## 可直接用于回答的表述

“我使用服务器主要是为了复用已经验证的 Linux GPU 环境，并持续运行多组训练和仿真对照。服务器不是算法上的必要条件，兼容的本地 GPU 也能运行这类小规模实验。服务器能帮助提高实验效率，但不会天然提高模型准确率；结果仍要通过相同数据、配对初始化、固定预算和独立场景评估来验证。”

## 容易被追问的点

- 用服务器是否说明模型太大：不能这样推断。本次单个训练进程的实际显存需求远低于整张卡的容量，选择服务器同时考虑环境和持续运行能力。
- 换服务器会不会提高成功率：单纯更换硬件没有这个保证。需要控制权重、数据、随机性和数值设置，区分运行效率与模型效果。
- 为什么保留不成功的优化：负结果也能检验假设。已完成的均衡采样多种子结果和视觉预训练对照，都不支持直接宣称稳定提升。
- 并行运行的时间能否当作性能成绩：不能直接使用。共享GPU时会相互争用资源，独立性能测量需要单独运行并注明预热、同步和计时边界。
